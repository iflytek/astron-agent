# 01 内部账号与 Python 控制台基础

父需求：[Python Console 与统一 Agent](../requirements.md)。依赖：无。本轮唯一实现范围。

## 范围

建立 Python 控制台可运行服务、数据库迁移和测试基础；实现内部用户名密码账号、用户资料及登录前端。替换 Casdoor 登录、回调、令牌刷新、退出与对应 SDK、部署依赖。当前服务只承接本范围，未迁移的业务允许暂时不可用，不代理回 Java。

## 行为与验收

- A1：未登录用户能在产品内注册，用户名唯一，密码经框架校验和哈希存储；重复名和无效密码返回可理解错误。注册不能指定 UID、管理员标记、空间角色或资源所有者。
- A2：用户以用户名密码登录，刷新页面保持登录；错误密码、冻结/删除账户不被认证。退出使该会话失效。用户可查看和修改自己昵称/头像、修改密码，不能修改他人资料。
- A3：以同源会话机制认证，状态修改校验 CSRF，登录轮换会话，敏感响应不缓存；错误信息和日志不输出密码、令牌或完整个人资料。登录/注册有基本请求速率限制。
- A4：从现有 `user_info` 导入账号，原 UID、资料和资源关联不变；原始业务表不清空、不重新初始化。旧用户使用不可登录的初始密码状态，管理员经命令行发放有时效、一次性重设链接。成功设置密码后原链接不可复用，登录仍使用原 UID；冻结/删除账号不能借重设激活。重设不需要邮箱。
- A5：同名、空 UID 或不合法历史用户名等冲突必须明确拒绝或由管理员显式映射，不静默合并用户。重复导入不覆盖已设的新密码。导入前不允许公开注册抢占旧账号名。
- A6：新空数据库可初始化和注册；现有数据库可非破坏地新增认证表、导入账号。多实例共享会话及限流状态，重启不丢失账号。
- A7：前端登录、注册、退出、重设密码和账号页面实际可操作，不调用 Casdoor、旧 OAuth 回调或令牌刷新；不引入旧登录兼容分支。
- A8：Python 服务与前端可构建、部署；删除被替代 Casdoor 文件和认证配置。Compose/Helm 的当前登录路径由 Python 负责，相关旧 CI 改为有效检查。

## 范围外

空间/企业角色管理和资源 CRUD 归 02；Agent、工作流、发布渠道分别归 03—05。本范围保留这些数据，不为了让旧功能暂时可用而保留 Java 认证或双后端运行。未迁移内部业务端点保持拒绝访问，不绕过认证。账号重设链接由受信任运维核实身份后交付；不建设短信、邮件、SSO 或第三方账号登录。
