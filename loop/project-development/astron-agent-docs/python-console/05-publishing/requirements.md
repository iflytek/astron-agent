# 05 发布渠道与完整产品交付

父需求：[Python Console 与统一 Agent](../requirements.md)。前置：04 工作流执行与 Agent 引用可用，01—03 已验收。

## 范围与验收

- 迁移应用/API 发布、密钥与网关鉴权、发布审批、Agent 市场上架、分享、微信渠道、语音/虚拟人/说话人相关管理及剩余发布分析功能。
- 发布成功以完整不可变快照切换最新发布版本，撤销与失败不制造半发布状态；04 的新运行可以解析新版本，运行中的版本不漂移。
- 本轮仅改造 Astron Agent，完全移除本项目的 Casdoor 依赖与联合登录配置。RPA 是独立项目，其联合登录、账号体系、源码、镜像和部署不在本轮范围；保留 Astron Agent 已有的 RPA API Key 资源与执行能力，不宣称外部 RPA 已完成身份迁移。
- 网关公开调用继续校验应用身份/权限，服务间凭据与浏览器登录分开；公开 API、渠道回调、SSE、工作流恢复和工具反向调用完成联调。
- 在所有业务域已迁移基础上逐项对照迁移前控制器/任务/渠道清单，恢复遗漏的用户能力；不得用空接口或统一返回成功代替旧业务。
- 删除全部剩余 Java 后端、Maven/JDK/Spring 构建依赖、Casdoor 文件/配置、陈旧文档和无效测试。更新模块说明、开发/部署/CI 与运行命令，确认新环境安装和已有数据库升级。
- 完成产品端到端验收：登录、空间、资源、独立 Agent、工作流、Agent 引用、发布与共享；保留用户数据和资源归属。
- 本轮按用户明确要求不执行微信开放平台真实环境验收；微信迁移仍需本地协议、权限、签名、幂等和错误处理测试，其他未明确豁免的真实验收仍须通过。
- 本轮按用户明确要求跳过语音合成、实时转写和声音训练的真实外部验收；保留相关配置、权限、签名及错误处理测试，虚拟人及其他适用产品流程继续验收。
- 用户明确废弃的3条旧市场发布（bot13、25、40）按业务软删除处理，不再作为恢复验收对象；其他历史数据仍遵循保留要求。
- 全部子需求和最终环境验收通过后才可交付为完整迁移；是否合并/上线遵循用户当前授权，不把中间阶段当作完成。

本需求负责发布渠道与最终产品完整性；不得重复实现前四项已拥有的账户、资源、Agent 内核和工作流调度。
