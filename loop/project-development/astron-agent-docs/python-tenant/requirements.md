# Tenant Python 迁移需求

## TENANT-01 服务兼容

将 `core/tenant` 替换为 Python 服务。保留 `/ping` 与 `/v2/app` 下的应用管理和密钥接口、业务状态码、响应字段及默认端口。由 Console 管理空间、成员及资源授权。Agent 和 Workflow 继续使用现有内部 HTTP 接口。

## TENANT-02 数据与凭据

复用 MySQL 的 `tb_app`、`tb_auth` 和迁移历史。空库可初始化，存量库升级后原有应用 ID 和有效凭据可继续使用。应用创建及其首个凭据需同时提交。删除应用会撤销其凭据，禁用应用会阻止凭据认证。启动凭据从部署环境或挂载文件加载，支持已有凭据接管、轮换和冲突时回滚。

## TENANT-03 构建与运维

原有服务名、镜像名、MySQL 连接配置和启动凭据注入方式继续使用。删除 Tenant 的 Go 源码、依赖锁和专用构建检查配置，将 Tenant 纳入 Python 构建、检查及测试。中英文项目文档与本地启动说明同步更新。

## 验收

用 Python 测试覆盖全部业务路由、鉴权与错误响应。用隔离 MySQL 验证新库、存量库、应用及 API Key 生命周期与启动凭据轮换。验证 Compose、Helm 渲染及对应部署检查，通过配置的 Loop 环境检查部署和上游调用。
